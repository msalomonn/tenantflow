# TF-03 project lifecycle contract — 2026-11-05

Scope: T010, issue #4, TF-A03–A06/A09 and revocation checks from A08. Existing approved role matrix remains authoritative. No deletion, restore/archive browser, invitation flow or deployment is added.

- P01: `PATCH /api/organizations/:orgId/projects/:projectId` accepts exactly one of `{name:string}` or `{archived:true}`. Names are trimmed, 1–120 Unicode code points; null bytes, unknown fields, empty objects and attempts to change tenant/ID are rejected with 400. Never accept `archived:false` as an undocumented restore.
- P02: owners/admins/members may mutate projects; viewers receive 403 for an existing project in their organization. Missing/inaccessible organizations and foreign/missing project IDs return 404 without changes. All protected requests require a valid session (401) and existing exact-origin JSON rules. Membership is read on each request and UPDATE is independently restricted by RLS and column grants.
- P03: archive sets a timestamp, hides the project from default lists and search, and retains its row. Authorized detail returns its metadata including archived_at. Repeated archive returns 200 with the original timestamp. Renaming an archived project returns 409. Serialize rename/archive for each project; no concurrent rename can revive an archived row. Concurrent renames use last committed write wins, without collaborative editing guarantees.
- P04: `PATCH /api/organizations/:orgId` accepts only `{name:string}` under the same name rules. Owner/admin may rename; member/viewer gets 403; outsider gets 404. Identity, memberships and organization ID stay unchanged. UI refreshes the selected workspace label after success.
- P05: project cards expose Edit and Archive only for writers. Edit pre-fills the current name, supports cancel/Escape, keeps input on recoverable failure and reports errors accessibly. Archive requires an explicit confirmation explaining that data is retained; cancel changes nothing. Show pending state and success feedback. Preserve loading, empty/search-empty, read-only, error and retry states.
- P06: changing workspace or role unmounts dialogs and cancels its outstanding requests. Late responses must not change the next workspace, its forms, selection or session. On 401 return to authentication; on 403/404 refresh authoritative access, clear unavailable records and keep actionable feedback when the actor still has access. On 409 reload the list so a concurrently archived project disappears. No optimistic cross-tenant cache updates.
- P07: real PostgreSQL tests cover role matrix, guessed/cross-tenant IDs, forged headers, column/RLS restrictions, pooled context reset, invalid names/payloads, revocation, repeat/concurrent archive and API-instance replacement. Browser tests cover edit/cancel/rename organization/archive/reload, read-only controls, error recovery and switching during delayed mutation. Record desktop/mobile screenshots with synthetic data.
