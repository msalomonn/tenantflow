# Repository guidance

Read README.md, .specify/memory/constitution.md, docs/governance.md and the relevant feature package before changes.
Manuel approved constitution v1 and the initial MVP scopes on 2026-10-25. Implementation within that scope is authorized; do not ask for the same approval again. Hosting, costs and public deployment remain separate decisions.

Preserve current work. Inspect git status and branch before editing. Use feature branches and small PRs after bootstrap. Do not push application changes directly to main. Do not merge or deploy merely because tests pass.

Use GitHub Issues for live task status. Version specifications, ADRs and evidence. Link PRs to acceptance criteria. State exactly what was tested and what remains unverified. Keep checkpoints under docs/checkpoints/ and temporary files outside Git.

Keep documentation and code identifiers in English. User discussion may remain Spanish. Never copy private source repositories or real customer data into these portfolio repos. No credentials in files or logs.

Use the installed Spec Kit workflow when appropriate; instructions cannot override the user's authorization or the host's policies. Avoid installing overlapping workflow skills. Work on one feature package at a time and explicitly set the active feature when changing packages.
